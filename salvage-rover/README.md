# 回收救援车

三个槽拼一辆废料救援车，按一下就自动跑完一条短路线。零件放在哪、这一趟装几箱，会改变两侧承重、耗电、能不能过坡，以及最后带回几箱。数字不会只变大：宽履能过软地但很重，绞盘只有装在车头才拉得动陡坡，货装太满会在坡上把电耗尽。

这一夹目录就是页面，没有编译步骤。资源都写在本目录里，用相对路径。

## 本地打开

在仓库根目录：

```bash
python3 -m http.server 8000
```

浏览器打开 `http://127.0.0.1:8000/salvage-rover/`。

## 操作

点一个零件，再点一个槽。点已经放上的零件，再点另一个槽，就是挪过去。点它现在的槽，就是取下。不要拖拽。

- 少装 / 多装：有货箱时，设定这一趟最多装几箱。路上没有那么多货，就只装到有的为止。
- 试车：按固定步数把这条路跑完。按钮在跑完后变成再试一次，用当前装配重跑一趟。
- 重置装配：只把这条路的零件放回起点，不清关卡进度。
- 重置进度：三条路和已解锁零件都回到最初。

桌面键盘：`1`–`4` 选电池、货箱、绞盘、宽履，`Q` `W` `E` 放到前、中、后槽，`Enter` 试车，`0` 重置装配，`-` `/` `=` 改装载。

手机和桌面是同一套点选。车看侧视图，镜头跟着车走。试车中的画面快慢不参与结算。

## 规则

和页面里的「规则」相同。

- 车架给前轴、后轴各 1 点承重。零件的重量算在它所在的槽。中槽平分到两边，多出来的 1 点算后轴。
- 电池放前槽驱动前轮，放后槽驱动后轮，放中槽不驱动。电量固定 60，通关不会把电池变大。
- 货箱空重 2。每装 1 箱再加重 2，最多 3 箱。
- 上坡时后轴比前轴重，前轮离地，当步停下。
- 缓坡要驱动轮承重至少 2。陡坡至少 6。绞盘只有在前槽，陡坡才加 4 点拉力，并且那一步多耗 1 点电。
- 没有宽履会陷进软地。软地每步多耗 3 点电。上坡每步再耗掉当时的总承重。平路每步 1 点。
- 到达回收旗时，车上的箱数要达到目标。

失败会停在那一步，并写明原因，例如前轮离地时的两侧承重、打滑时驱动轮差多少、没电时这一步要多少还剩多少。

## 三条路

| 路 | 目标 | 能送到的一种装配 | 换一种会怎样 |
| --- | --- | --- | --- |
| 坡底试车 | 1 箱 | 货箱在前槽，电池在后槽，装 1 | 货箱留在中槽：停在坡底，前轮离地（前 2 / 后 3） |
| 陡坡减载 | 2 箱，地上有 3 | 绞盘在前槽，货箱在中槽，电池在后槽，装 2 | 装 3：陡坡上电量耗尽。装 1：车到了但箱数不够。绞盘不在前槽：拉不住。用宽履换掉绞盘：驱动轮打滑 |
| 软地回运 | 2 箱，地上有 3 | 宽履在前槽，货箱在中槽，电池在后槽，装 2。货箱在前、宽履在中、电池在后也可以 | 不装宽履：陷进软地。宽履放后槽、电池放前槽：装上货之后前轮离地。装 3：缓坡上电量耗尽 |

坡底试车通关后打开绞盘和陡坡。陡坡通关后打开宽履和软地。进度在本地 `localStorage` 键 `salvage-rover-progress-v1`。

## 和设计说明的差别

- 装配是点选，不是拖放。手机上拖零件容易被手指挡住。
- 后槽连着后轮。教程先把电池放进后槽，货箱还在中槽，车会在坡底抬头；再把货箱点到前槽就能过去。
- 承载用「本次装载」限制，不是再做一种货箱。同一套零件，装 1、2、3 箱的结果不同。
- 结算是离散的承重和电量，不假装成连续物理。画面只回放已经算完的步。
- 车只开到回收旗，不原路开回车库。
- 没有音效、广告、账号、付费和服务器。解锁只是打开下一条路和对应零件，没有永久加成。

## 检查

规则测试不需要额外安装：

```bash
node --test salvage-rover/sim.test.js
```

浏览器冒烟使用仓库根目录已有的 Playwright，本目录不另装依赖：

```bash
npm ci
npx playwright install chromium
node salvage-rover/browser-smoke.js
```
