# 第一款游戏设计文档

## 一、三个候选方案

| | A. 叠叠高（Stack Tower）✅首选 | B. 合成掉落（数字/水果合成） | C. 放置经营（AI 实验室大亨） |
|---|---|---|---|
| 核心循环 | 方块左右移动 → 点击落下 → 超出部分被切掉 → 塔越高越窄越快 → 掉空结束 → 看分数 → 再来一局 | 选位置投放物件 → 同类碰撞合成更高级 → 空间被填满结束 | 点击/自动产出资源 → 买升级提升产速 → 解锁新建筑 → 离线收益 → 转生重置换倍率 |
| 为什么适合 | 单键操作、30 秒一局、规则零学习；纯代码几何美术就能好看；手机竖屏天然适配；完美对齐/连击有爽点，易做短视频 | 已被验证的爆款品类（合成大西瓜），留存好；物理引擎 Phaser 自带 | 前端擅长的 UI/数值类，适合 CrazyGames 长时长；可结合 "AI 实验室" 人设做内容 |
| 开发周期 | 原型 1 天，可上线版 1–2 周 | 原型 2–3 天，可上线 2–3 周 | 原型 3–5 天，可上线 4–6 周（数值平衡、离线收益、存档迁移耗时） |
| 广告位 | 结束页激励视频「复活一次」；每 2–3 局插屏；激励「双倍金币」解锁皮肤 | 满屏时激励「清理一行/摇一摇」；插屏局间 | 激励「2 倍产速 x 分钟」「离线收益翻倍」；几乎不用插屏 |
| 风险 | 品类同质化，需靠手感/皮肤/主题做差异 | 同类竞品极多，物理调参费时 | 数值设计门槛高，首款容易做不完 |

**首选 A：叠叠高。** 理由：范围最小、能最快走完「做→发→看数据」全流程（报告第一阶段目标就是拿真实留存数据）；单键 + 竖屏 + 短局同时适配 itch.io/CrazyGames 网页、手机浏览器和之后的微信小游戏；激励视频「复活」是 IAA 最自然、收益最好的位；过程直观，适合小红书「Stone的AI实验室」录屏做 Build in Public。B 作为第二款，C 等积累后再做。

## 二、首选方案设计

- **画面**：720×1280 逻辑分辨率，Scale.FIT 居中，竖屏优先，桌面也可玩。占位美术全部为代码绘制的矩形，颜色按层数 HSV 渐变。
- **操作**：点击/触摸屏幕任意处，或空格键，落下当前方块。
- **规则**：
  - 底座宽 400。新方块从左右交替出现、来回移动。
  - 落下后与下层重叠部分保留，超出部分被切掉并掉落；完全没重叠 → 游戏结束。
  - 偏差 < 8px 记为「完美」：自动对齐、+2 分；连续完美 ≥3 次每次宽度 +20（上限 400）。普通落下 +1 分。
  - 速度随层数上升（300 → 最高 800 px/s）。镜头随塔高上移。
- **流程**：主菜单（最高分、已玩局数）→ 游戏 → 结束页（得分 / 新纪录 / 再来一局 / 主菜单）。
- **存档**：localStorage `stackTower.best`、`stackTower.stats`（局数、累计方块）。移植微信时换成 `wx.setStorageSync`。
- **广告钩子**：`gameOver()` 中已标注 TODO 广告位（激励复活 + 插屏频控）。
- **后续可加**：音效与震动、皮肤/主题（用金币解锁）、每日挑战（固定种子）、排行榜、分享截图。

## 三、3 个月里程碑

| 时间 | 目标 | 交付 / 指标 |
|---|---|---|
| 第 1–2 周 | 打磨原型：手感、音效、粒子、震动、3 套配色主题；接入简单埋点（局数、单局时长、次日回访） | 内部可玩版；小红书发 2–3 篇开发记录 |
| 第 3–4 周 | 上线 itch.io（HTML 游戏）+ 提交 CrazyGames Basic Launch；接 CrazyGames SDK 广告（激励复活、插屏） | 公开链接；收集首批数据：平均局数/人、D1 留存 |
| 第 5–6 周 | 按数据迭代：难度曲线、复活频率、皮肤系统 + 金币；做每日挑战 | D1 留存目标 ≥ 25%，平均每人 ≥ 5 局 |
| 第 7–9 周 | 移植微信小游戏（Phaser 适配层或改用 Cocos/原生 Canvas 评估）；核实个人主体上线 & 无版号备案要求；接微信流量主广告 | 微信小游戏提审 |
| 第 10–12 周 | 微信上线与买量/分享测试；复盘决定：继续加深 A，或开第二款（方案 B）；小红书阶段性复盘长文 | 复盘报告：留存、eCPM、单用户广告收入 |
